# Cabinet → admin wizard parity

Дата перевірки: 2026-10-12. Перевірено локальний код main та worktree `lead-cabinet-design-bugs-5fa969`.

## Межі та результат

Цей звіт звіряє **8 конкретних пунктів наданого переліку** та пов’язані з ними джерела полів сучасного кабінету. Оригінального `qa/cabinet-to-wizard-matrix.md` немає в обох checkout та початковому workspace; висновок про повну перевірку «113 полів» не робиться.

У коді закриті всі 8 пунктів. Це перевірка маршруту даних, умов відображення та синтетичних тестів, **не підтвердження роботи опублікованого сервера або конкретного ліда**. Нові backend поля потребують відповідної версії API. Живі медичні дані, remote API та записи БД під час цього аудиту не змінювалися.

## Карта пов’язаних полів сучасного кабінету

Інвентар виконаний за AST type literals та явним catalog BillingExtrasField сучасного worktree, а не за старим відсутнім звітом. Перші дев’ять груп нижче містять **119 named draft slots**. Це ключі форм, включно з routing state та legacy aliases, а не 119 незалежних видимих inputs на кожному екрані. Представник — одна шаблонна структура для `agent/guardian/rep1/rep2`; повторні особи, файли та умовні блоки не множилися в це число. Додаткові consent/questionnaire групи наведені окремо.

## Перевірки та практичні межі

- У main та worktree пройшли **107 targeted tests**: GWG model, GWG view та payer UI. Після наступного узгодження warning frames окремо пройшли **41 GWG UI test** в обох checkout.
- Завершальний запуск трьох consent/portal suites дав **12 passed tests** у кожному checkout: zero-upload medical consent, grant/revocation, all 8 Anlage 1 choices, actor/date, null semantics та restricted roles.
- Scoped ESLint і `git diff --check` для model/view змін пройшли. Загальні frontend typecheck і Rust compile виконує root task після інтеграції.
- Public/remote deployment не підтверджено цим статичним аудитом. Якщо backend не повертає нові поля, frontend не вигадує дані. На main без нового choice store/collector Anlage 1 не може відновитися з самого PDF.
- Organisation mask із нечинним payer marker свідомо прихована. Це запобігає показу даних попереднього платника; для такого запису потрібне чинне джерело cabinet statement, а не припущення з попереднього документа.
