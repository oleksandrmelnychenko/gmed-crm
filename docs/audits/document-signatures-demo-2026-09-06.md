# Живий DEMO-тест Skribble у GMED — 06.09.2026

Повний цикл перевірено на `console-dev.gmed-health.com` із німецьким
Skribble (`api.skribble.de/v2`). Це реальні HTTP-запити до DEMO API,
без підставних відповідей. Режим QES не вмикався.

## Підключення й результат

- За явним дозволом користувача створено DEMO-ключ із описом
  `GMED integration test`. Через сторінку GMED `/admin/signatures`
  виконано «Проверить и подключить», потім «Проверить соединение».
  Обидві дії успішні; поле ключа очищене після збереження.
- Створено синтетичний односторінковий PDF із позначкою DEMO,
  без пацієнтських даних, договорів або фінансових зобов'язань.
  Файл збережено через штатний `/documents/upload` з `manual_intake=true`.
- У картці документа натиснуто «Электронная подпись», заповнено одного
  тестового підписанта (акаунт, наданий користувачем), підтверджено PDF
  і адресу, відправлено один запит.
- Skribble показав запрошення DEMO. Після підписання показав
  `Signatur erfolgreich!` та `SIGNED`.
- GMED автоматично отримав підписаний PDF і PDF-протокол, завершив
  запит та показав «PDF и отчёт сохранены». Кнопка ручної синхронізації
  під час перевірки не використовувалася.

## Відновлення після тимчасової помилки

Перший цикл отримання файлів після підписання повернув
`provider_http_error`. Підпис зберігся, а запит залишився `pending`.
Наступна фонова спроба успішно зберегла обидва PDF й очистила помилку.
Повторне відправлення або ручне перенесення результатів не знадобилося.
Точний HTTP-код першої невдалої відповіді не був збережений.

## Межі перевірки

Інструмент керування вбудованим браузером не передав вибраний локальний
файл у `input[type=file]`, тому завантаження початкового PDF виконане
через штатний API GMED. Подія браузерного завантаження результату також
не була підтверджена інструментом; отримання байтів обох файлів
підтверджене окремим авторизованим GET через API. Це не доказ помилки
ручного завантаження у звичайному браузері.

Підключення, відправлення запиту, DEMO-підпис і показ завершеного стану
перевірені через живий інтерфейс. Платні підписи, реальна QES-ідентифікація,
двоє підписантів, відмова та відкликання до цього прогону не входили.
Зміни коду або розгортання для завершення цього прогону не знадобилися.
Пароль, API-ключ і токени не збережені в цьому звіті чи файлах репозиторію.
